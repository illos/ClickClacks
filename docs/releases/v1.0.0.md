# ClickClacks v1.0.0

Version one packages the existing TypeScript library, optional React/Three.js
presentation and reusable Convex component. This release changes distribution
and documentation; it does not change dice results, graphics or the hosted UI.

## Install

```sh
pnpm add 'clickclacks@https://github.com/illos/ClickClacks/releases/download/v1.0.0/clickclacks-1.0.0.tgz'
```

Commit the resulting lockfile. The versioned release asset and its lockfile
integrity pin the package; do not depend on `main`. npm publication is deferred.
The release also contains `SHA256SUMS` for download verification.

The source exports need a TypeScript bundler, `vite/client` types and
`DOM.Iterable`. Optional 3D presentation requires the included Three.js
0.186.1 patch to be registered in the **consumer's** pnpm configuration;
dependency patches are not transitive. Follow [the embedding guide](../../README.md#embedding).

Convex 1.45.0 hosts install `clickclacks/convex.config.js`. The artifact includes
generated component bindings, fonts, their OFL notices, audio assets and the
Three.js patch. It contains no deployment credentials. Installing the component
does not expose browser endpoints; the host supplies authenticated wrappers.

## Release preparation

Use Node 24.18.0 and pnpm 11.5.3 in a clean checkout. Generate bindings against
an isolated development backend before packaging:

```sh
pnpm install --frozen-lockfile
env -u CONVEX_DEPLOY_KEY CONVEX_AGENT_MODE=anonymous pnpm exec convex dev --once --typecheck enable --typecheck-components
pnpm typecheck
pnpm pack --pack-destination /tmp/clickclacks-v1-release
```

The prepack check refuses missing exports, component bindings or font inputs.
Bindings and archives stay outside version control. Review the packed file list,
install the archive in an independent consumer and verify its component and
frontend build before publishing. Tag the reviewed source `v1.0.0`, upload the
archive and its checksum, and never replace a published version's artifact.

## Evidence and limits

The [implementation record](../v1-implementation.md) contains the accepted
library/component, installed-package, resource-budget and collaboration evidence
for the revisions named there. Later hosted-site changes are recorded separately;
those earlier measurements are not evidence for every browser/device or commit.
This release does not promise a particular phone frame rate or reveal spread.
The release packaging and Salient installation receive their own review and
verification before publication.
